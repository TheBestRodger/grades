# Агент учета входящих требований

## Назначение

Этот агент нужен, чтобы каждое новое сообщение заказчика не растворялось в переписке. На входе он классифицирует замечание, связывает его с существующими фичами и обновляет реестр `docs/FEATURE_REGISTRY.md`.

## Классы входящих сообщений

| Класс | Когда ставить | Что делать |
|---|---|---|
| `NEW_FEATURE` | Пользователь просит новую возможность | Создать новую строку в реестре |
| `CHANGE_EXISTING` | Пользователь меняет уже сделанную механику | Обновить существующую строку, не создавать дубль |
| `CLARIFICATION` | Пользователь уточняет правило или бизнес-смысл | Добавить уточнение в существующую строку и критерии приемки |
| `BUG_OR_GAP` | Пользователь говорит, что сделано не так или не видно | Пометить как `PARTIAL` или `OPEN`, добавить проблему |
| `DUPLICATE` | Требование уже есть без новых деталей | Сослаться на существующий ID |
| `QUESTION` | Пользователь спрашивает состояние или варианты | Ответить по реестру, без изменения статуса, если не появилось новое требование |

## Статусы

| Статус | Значение |
|---|---|
| `DONE` | Реализовано, проверено тестом/сборкой/браузером или документом |
| `PARTIAL` | Есть рабочая основа, но не закрыт весь бизнес-сценарий |
| `OPEN` | Не реализовано |
| `DEFERRED` | Осознанно отложено после MVP |
| `BLOCKED` | Нельзя делать без решения заказчика или внешних данных |
| `DUPLICATE` | Отдельно не делать, покрывается другой строкой |

## Обязательный процесс

1. Перед крупной разработкой просмотреть `docs/FEATURE_REGISTRY.md`.
2. Для каждого нового пользовательского замечания определить класс входа.
3. Если это новая фича или существенное уточнение, обновить реестр до или во время реализации.
4. После реализации обновить статус, критерии приемки и доказательство: тест, сборка, файл, endpoint или браузерная проверка.
5. Если пользователь спрашивает “что осталось”, отвечать по реестру, а не по памяти.

## Поля записи

Каждая строка в реестре должна иметь:

- `ID`;
- `тип`;
- `статус`;
- `краткое требование`;
- `что сделано`;
- `что осталось`;
- `проверка / источник`.

## Правило анти-дублей

Перед созданием новой строки проверить похожие темы:

- роли и доступы;
- кампании и статусы;
- анкета/шаблон профиля;
- руководительская проверка;
- HR-финал;
- документы;
- анализ/аномалии;
- импорт/экспорт;
- portable-запуск;
- AI Gateway.

Если новая просьба уточняет существующую тему, обновлять существующий ID.
