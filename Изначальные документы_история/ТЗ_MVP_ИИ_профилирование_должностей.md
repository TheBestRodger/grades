# 1. Контекст и цель

Проект предназначен для автоматизации профилирования должностей в
университете с последующим использованием данных для грейдирования.
Профиль должен описывать реальную работу, а не только формальную
должностную инструкцию: задачи, функции, навыки, ответственность,
бюджет, сложность решений, коммуникации, полномочия, требования и
фактическое место должности в организационной структуре.

Ключевая идея: не строить сразу тяжелую HR-систему, а создать понятный
MVP, который быстро собирает качественные данные, сохраняет их в базе и
дает выгрузку/аналитику. ИИ подключается как помощник: уточняет ответы,
предзаполняет профиль из документов, подсвечивает расхождения и помогает
руководителю разобраться, где фактическая роль отличается от формальной.

| **Источник**                   | **Что берем в требования**                                                                                                                                                        |
|--------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ТЗ по профилированию           | Цель автоматизации, ИИ-агент, предзаполнение из ДИ/положений/оргструктуры, подсветка расхождений, сравнение профилей выше- и нижестоящих должностей, анализ дублирования функций. |
| Excel-шаблон профиля должности | 9 разделов профиля: общая информация, цель, обязанности, бюджет, сложность задач, коммуникации, полномочия, требования, комментарии.                                              |
| HTML-прототип формы            | Визуальный подход: трехколоночный интерфейс, чат, левое меню разделов, правый предпросмотр профиля, прогресс, быстрые ответы, экспорт.                                            |
| Обсуждение                     | Vite/React, легкая БД, руководительские срезы, ручная привязка документов, сверка с ДИ/положениями/профстандартами, LLM по токену, проценты соответствия и флаги расхождений.     |

# 4. Пользовательские сценарии

## Сценарий 1. Заполнение профиля носителем должности

1.  Пользователь открывает персональную ссылку.

2.  Видит приветствие, цель опроса, статус заполнения и разделы.

3.  ИИ задает вопросы по одному или блоками: закрытые варианты +
    свободный текст.

4.  Пользователь отвечает, система сохраняет каждый ответ сразу.

5.  ИИ уточняет слабые ответы: “Что является результатом для
    университета?”, “Каким бюджетом вы реально управляете?”, “Приведите
    пример сложной задачи”.

6.  После последнего раздела формируется черновик профиля и отчет
    расхождений.

## Сценарий 2. Руководитель проверяет вертикаль

7.  Руководитель входит в кабинет.

8.  Видит дерево своей вертикали: должности, статусы заполнения,
    прогресс, флаги расхождений.

9.  Открывает профиль подчиненного.

10. Видит сравнение: ответы сотрудника vs ДИ/положение/профстандарт vs
    профиль руководителя/смежных ролей.

11. Выбирает действие: согласовать, отправить на уточнение, отметить как
    фактическое расширение роли, оставить комментарий.

## Сценарий 3. HR привязывает документы

12. HR загружает пакет документов.

13. Система пытается распознать название должности/подразделение.

14. Если сопоставление не найдено, документ попадает в список
    “несопоставленные”.

15. HR вручную выбирает должность или подразделение и связывает
    документ.

16. Связка используется для предзаполнения и последующей сверки.

## Сценарий 4. Анализ дублирования функций

17. HR выбирает функциональную вертикаль или группу подразделений.

18. Система сравнивает обязанности, цели, коммуникации, полномочия и
    требования.

19. Выдает похожие профили, пересечения задач, потенциальные дубли,
    уникальные функции.

20. Отчет доступен только HR-проектной команде.

# 6. ИИ-логика и сверка документов

ИИ не должен быть единственным источником истины. Он выступает
помощником: задает уточнения, предлагает формулировки, извлекает факты
из документов, ищет расхождения и формирует объяснимые рекомендации. Все
важные выводы должны хранить ссылки на источник: ответ пользователя,
фрагмент ДИ, фрагмент положения, профстандарт, оргструктуру.

| **Функция ИИ**       | **Как работает**                                                                                              | **Что сохраняется**                                                  |
|----------------------|---------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------|
| Предзаполнение       | Извлекает из ДИ/положения цель, обязанности, требования, подчиненность, бюджетные формулировки, коммуникации. | Черновик поля + источник + confidence.                               |
| Уточнение ответов    | Проверяет ответ на полноту, конкретность, связь с результатом, наличие суммы/масштаба/примера.                | Оценка качества ответа и текст уточняющего вопроса.                  |
| Сверка документов    | Сравнивает профиль с ДИ, положением, профстандартом и оргструктурой.                                          | Тип расхождения, степень, цитируемый фрагмент, рекомендация.         |
| Сверка вертикали     | Сравнивает профили руководителя, подчиненных и смежных ролей.                                                 | Нестыковки по подчинению, зонам ответственности, дублированию задач. |
| Процент соответствия | Считает долю совпадающих/частично совпадающих/противоречащих пунктов по каждому документу.                    | score_total, score_by_section, список флагов.                        |
| Анализ дублирования  | Сравнивает обязанности и функции по смысловой близости между подразделениями.                                 | Пары похожих функций, уровень сходства, рекомендации HR.             |

## 6.1 Типы расхождений

| **Тип**                                 | **Пример**                                                                 | **Действие**                                                                       |
|-----------------------------------------|----------------------------------------------------------------------------|------------------------------------------------------------------------------------|
| Нет в ДИ, но есть в фактическом профиле | Сотрудник управляет бюджетом, но в ДИ это не указано.                      | Руководитель подтверждает фактическую роль или отправляет на уточнение.            |
| Есть в ДИ, но нет в фактическом профиле | В ДИ указано взаимодействие с госорганами, сотрудник пишет “не применимо”. | Проверить актуальность ДИ или полноту ответа.                                      |
| Противоречие оргструктуре               | Сотрудник указывает руководителя, отличного от актуальной структуры.       | Подсветить HR и руководителю, уточнить административную/функциональную линию.      |
| Выход за профиль                        | Специалист описывает полномочия уровня руководителя.                       | Попросить уточнить: это разовое поручение, фактическое расширение роли или ошибка. |
| Дублирование функций                    | Две вертикали описали одинаковую ответственность за один процесс.          | HR анализирует пересечение и готовит решение по разграничению.                     |

## 6.2 Правила безопасной работы с LLM

- LLM вызывается через токен/API key, хранящийся только на backend в
  переменных окружения.

- В запрос модели не отправлять лишние персональные данные; достаточно
  роли, поля анкеты, ответа и обезличенного контекста.

- Для каждого ответа модели сохранять structured output: verdict, score,
  missing_details, follow_up_question, suggested_value, sources.

- Все автоматические выводы показывать как “предложение ИИ”, а не как
  окончательное решение.

- Нужен режим без LLM: анкета и сохранение должны работать даже при
  недоступности модели.

# 7. Требования к интерфейсу

Базой можно считать существующий HTML-прототип: шапка с брендингом МГТУ,

| **Экран/компонент**        | **Требования**                                                                                                                                 |

| Руководительский dashboard | Дерево подчинения, прогресс по сотрудникам, фильтр по расхождениям, карточка профиля, решения руководителя.                                    |
| HR dashboard               | Все профили, документы, привязки, несопоставленные документы, аналитика дублирования, экспорт.                                                 |
| Документы                  | Список загруженных документов, тип, статус сопоставления, привязанная должность/подразделение, источники извлечения.                           |
| Дизайн                     | Современный аккуратный интерфейс в стиле текущего прототипа: синий основной цвет, светлый фон, карточки, мягкие тени, читабельный Inter/Arial. |

## 8.1 Экспорт

- Excel по шаблону “Профиль должности”: заполнить соответствующие поля и
  сохранить отдельным файлом.

- CSV: плоская таблица профилей и ответов для аналитиков.

- JSON: полный профиль, ответы, источники, расхождения, статусы и
  история.

- Отчет для руководителя: список профилей вертикали, проценты
  соответствия, критичные расхождения, решения.

# 12. Критерии приемки

- Можно создать пользователя/должность и открыть персональную анкету.

- Пользователь проходит все 9 разделов, ответы сохраняются и не теряются
  после перезагрузки страницы.

- Правый предпросмотр показывает заполненный профиль и статус полей.

- Экспорт Excel формируется по структуре шаблона профиля должности.

- Документ можно загрузить, увидеть в списке и вручную связать с
  должностью/подразделением.

- LLM-уточнение работает для открытых вопросов и не блокирует заполнение
  при ошибке API.

- Система формирует минимум 3 типа расхождений: нет в ДИ, есть в ДИ но
  нет в ответе, противоречие оргструктуре.

- Руководитель видит дерево своей вертикали и профили подчиненных.

- HR видит все профили, расхождения, несопоставленные документы и
  экспорт.

- Все решения руководителей и правки ответов попадают в аудит-лог.

## 13.4 Что не делать в MVP

- Не строить полноценную HRIS/грейдинг-систему сразу.

- Не давать ИИ автоматически менять профиль без подтверждения
  пользователя/руководителя.

- Не прятать расхождения: нужны понятные причины и источники.

- Не блокировать заполнение, если LLM недоступна.

- Не начинать с идеальной интеграции со всеми корпоративными системами;
  сначала рабочий импорт/экспорт и ручные связки.
