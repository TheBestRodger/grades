# Импорт данных и демонстрационная ветка

## 1. Доступные исходные материалы

| Источник | Содержание | Роль в системе |
|---|---|---|
| `ШР по уровням на 15.05.26.xlsx` | 4 667 строк, 5 уровней структуры, должность, ставок по ШР и занято | Импорт штатных строк и дерева подразделений |
| `backend/source_documents/Intrukcii_i_pologeniya/` | OCR-тексты ДИ и положений, а также журнал распознавания | Будущий реестр документов и привязки |
| `backend/source_documents/Изначальные документы_история/` | Архивные материалы, шаблон и HTML-референс | Не нормативный источник; применяется только как референс |

Штатный Excel не содержит ФИО, email и непосредственных руководителей конкретных людей. Для реального пилота понадобится отдельный импорт назначений сотрудников либо ручное наполнение HR.

## 2. Импорт структуры

Импорт структуры должен:

1. Сохранять файл и снимок импорта.
2. Создавать/актуализировать `OrgUnit` по уровням структуры.
3. Создавать `StaffingLine` по сочетанию пути подразделения и должности.
4. Хранить `approved_fte` и импортированное `reported_occupied_fte`.
5. Выявлять технические проблемы, не смешивая их с содержательными сигналами.

Проверки импорта:

- отсутствует должность;
- некорректная числовая ставка;
- конфликт одной строки между версиями импорта;
- дубликаты, требующие подтверждения правил агрегирования.

Вакантная ставка не является ошибкой.

## 3. Добавление сотрудников HR

HR должен иметь три режима:

| Режим | Поведение |
|---|---|
| Один сотрудник | Форма сотрудника и назначения |
| Несколько сотрудников | HR указывает число; появляется таблица нужного числа строк |
| CSV/XLSX | Импорт сотрудников и назначений с предварительной валидацией |

Минимальные поля:

| Поле | Обязательность |
|---|---|
| ФИО | Обязательно |
| Email | Обязательно для реального доступа; в демо может быть тестовым |
| Штатная строка / должность и подразделение | Обязательно |
| Доля ставки | Обязательно, по умолчанию `1.0` |
| Непосредственный руководитель | Обязательно для маршрута проверки |
| Внешний кадровый ID | Опционально до реального кадрового импорта |
| Признак активности | Обязательно |

Система показывает остаток ставок, но множественные назначения на должность считаются нормой.

## 4. Импорт документов

Документы хранятся как карточки реестра с кодом, названием, типом, версией и ссылкой на оригинал/извлечённый текст.

Для OCR-материалов необходимо сохранять:

- исходное имя файла;
- checksum для поиска дублей;
- сведения о качестве OCR и предупреждениях;
- статус проверки HR;
- подтверждённые привязки к подразделениям/позициям.

Показатели документного покрытия:

```text
ДИ: подтверждено N из M требуемых штатных позиций
Положения: подтверждено N из M подразделений
Профстандарты: подтверждено N из M применимых ролей
```

Знаменатель считается только по объектам, для которых документ соответствующего типа требуется или применим.

## 5. Демонстрационная ветка

Демо-ветка создаётся как отдельный seed-набор с `is_demo = true`:

```text
Ректор / Эйчар Эйчарович Эйчаров / роль HR
└── Проректор по тестовым делам / Тестов Тест Тестович-2
    └── Тестовое направление / Директор тестового направления / Тестов Тест Тестович-3
        └── Тестовый отдел / Начальник тестового отдела / Тестов-4 Тест-4 Тестович-4
            └── Тестировщик / Тестов Тест Тестович
```

Для демонстрации массового назначения штатная строка `Тестировщик` может иметь `approved_fte = 8`, при начальном назначении одного сотрудника.

## 6. Демо-функции

| Позиция | Цель | Функции |
|---|---|---|
| Проректор по тестовым делам | Обеспечивать управление тестовым контуром демонстрационного проекта | Утверждает правила проверок; контролирует критические риски; рассматривает отчёты |
| Директор тестового направления | Организовывать работу направления и качество результатов | Планирует; распределяет ресурсы; контролирует показатели |
| Начальник тестового отдела | Организовывать ежедневные проверки демонстрационных сервисов | Назначает сценарии; проверяет дефекты; возвращает результаты на исправление |
| Тестировщик | Проверять корректность демонстрационных функций приложения | Выполняет сценарии; фиксирует ошибки; перепроверяет исправления |

Одинаковое слово `проверяет` или `тестирует` не считается дублированием: проверяется объект работы, результат и уровень ответственности.

## 7. Синтетические документы

Документы создаются исключительно для демо-ветки:

| Код | Тип | Название | Привязка |
|---|---|---|---|
| `DEMO-REG-001` | Положение | Положение о тестовом направлении | Демо-направление |
| `DEMO-REG-002` | Положение | Положение о тестовом отделе | Демо-отдел |
| `DEMO-DI-001` | ДИ | ДИ проректора по тестовым делам | Демо-позиция проректора |
| `DEMO-DI-002` | ДИ | ДИ директора тестового направления | Демо-позиция директора |
| `DEMO-DI-003` | ДИ | ДИ начальника тестового отдела | Демо-позиция начальника |
| `DEMO-DI-004` | ДИ | ДИ тестировщика демонстрационного отдела | Демо-позиция тестировщика |
| `DEMO-PS-001` | Профстандарт | Демо-профстандарт специалиста по тестированию | Демо-позиция тестировщика |

Правила защиты от смешения:

- в названии и интерфейсе указано `Демонстрационный документ`;
- связь устанавливается по ID демо-позиции/подразделения;
- автоматическая привязка к реальным одноимённым ролям запрещена;
- в рабочих метриках документы не учитываются.
