# ИИ-профилирование должностей

MVP системы профилирования должностей для серверного стенда.

Текущий этап:

- backend на FastAPI и SQLite;
- frontend на React/Vite, в Docker собирается в статические файлы и отдаётся backend-ом;
- рабочий контур с кабинетами HR, руководителя и сотрудника;
- вход по одноразовой email-ссылке;
- интеграция с OpenAI-compatible LLM;
- запуск через Docker для macOS, Linux и Ubuntu VM.

Актуальные архитектурные решения находятся в `docs/`, правила разработки - в `AGENTS.md`.

## Быстрый запуск через Docker

Рекомендуемый способ для macOS, Linux и Ubuntu VM:

```bash
cp .env.example .env
docker compose up -d --build
```

После запуска интерфейс доступен по адресу:

```text
http://192.168.18.163:8010
```

По умолчанию Docker-стенд работает в pilot-режиме:

```env
APP_ENV=pilot
PUBLIC_BASE_URL=http://192.168.18.163:8010
```

SMTP нужен только для сценария входа по одноразовой email-ссылке. Основной пилотный
вход сейчас работает по логину и паролю.

```env
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_USERNAME=login@example.ru
SMTP_PASSWORD=...
SMTP_FROM_EMAIL=login@example.ru
SMTP_USE_TLS=true
SMTP_USE_SSL=false
```

Для входа без SMTP используется логин/пароль. Первый HR-пользователь берётся из
seed-данных, а его логин и пароль задаются через `.env`:

```env
BOOTSTRAP_HR_USERNAME=hr
BOOTSTRAP_HR_PASSWORD=...
```

После входа HR добавляет руководителей и сотрудников в рабочую структуру. Для
каждого добавленного пользователя система генерирует логин и временный пароль;
HR скачивает XLSX с доступами и передаёт их пользователям.

Для внешней OpenAI-compatible LLM:

```env
AI_MODE=token
AI_PROVIDER=openai_compatible
OPENAI_BASE_URL=https://api.openai.com
OPENAI_MODEL=gpt-5-mini
OPENAI_API_KEY=...
AI_REQUEST_TIMEOUT_SECONDS=60
```

Compose подключает Docker volume `grades_mgtu_data` к `/app/backend/data`.
В контейнере backend запускается в один worker; SQLite работает в WAL-режиме
с `busy_timeout`.

Проверка после запуска:

```bash
docker compose ps
curl -s http://192.168.18.163:8010/api/health
```

Ожидаемо: контейнер `app` находится в статусе `Up` / `healthy`, healthcheck
возвращает `"status":"ok"`.

Полезные команды:

```bash
docker compose logs -f app
docker compose restart app
docker compose down
./scripts/backup_data.sh
```

Backup по умолчанию сохраняется вне папки проекта:

```text
../grades_mgtu_backups/<timestamp>/
```

Скрипт backup нужно запускать из корня репозитория при поднятом контейнере.

Можно указать другой каталог:

```bash
./scripts/backup_data.sh /var/backups/grades_mgtu
```

Если нужно полностью сбросить Docker-данные стенда, включая volume с SQLite и
документами:

```bash
docker compose down -v
```

На серверном стенде эту команду нельзя выполнять без backup.

## Быстрый запуск демо

На уже подготовленном Windows-компьютере откройте файл:

```text
start_demo.bat
```

Он запускает backend на `http://127.0.0.1:8010`, использует SQLite в `backend\data`,
режим `AI_MODE=off` и открывает браузер. Окно `start_demo.bat` нужно оставить открытым
на время показа: это окно сервера. Если приложение уже запущено на порту `8010`,
батник просто откроет текущий адрес.

Для остановки:

```text
stop_demo.bat
```

Для повторного показа можно сбросить только демонстрационный контур:

```text
reset_demo.bat
```

Сброс пересоздаёт демо-пользователей, демо-кампании, профили и демо-документы.
Рабочие данные (`is_demo=false`), импортированное ШР, рабочие сотрудники и рабочие
документы не удаляются.

## Перенос на другой компьютер

### Важное ограничение текущей версии

Папка `.venv` не является переносимой сборкой: в ней сохраняется путь к Python на
компьютере, где окружение было создано. Поэтому на новом ноутбуке нельзя полагаться
на скопированную `.venv`. Для текущей версии нужен установленный `Python 3.12 x64`
и одноразовая установка backend-зависимостей.

Node.js на компьютере показа не требуется, если передан уже собранный каталог
`frontend\dist`.

### Что передать

Перед копированием остановите демо через `stop_demo.bat` или `Ctrl+C` в окне сервера,
чтобы база SQLite была скопирована в согласованном состоянии.

Передайте папку проекта, обязательно сохранив:

- `start_demo.bat` и `stop_demo.bat`;
- `reset_demo.bat`, если нужен быстрый возврат демо-контура к исходному состоянию;
- `backend\`, включая `backend\data\demo.sqlite` для сохранения созданных кампаний,
  волн, привязок документов и профилей;
- `frontend\dist\`;
- `Изначальные документы_история\`, в том числе размеченный файл штатного расписания
  и Excel-шаблон экспорта профиля;
- `Intrukcii_i_pologeniya\`;
- `README.md`.

Необязательно переносить `.venv`, `frontend\node_modules`, `.pytest_cache`,
`backend\data\migration_check*.sqlite` и файлы `backend\data\*.log`. Они не нужны
для запуска переданной рабочей базы.

### Первый запуск на новом ноутбуке

1. Установите `Python 3.12 x64` для Windows. При установке удобно включить опцию
   добавления Python в `PATH`.
2. Распакуйте проект, например в `C:\Profilirovanie`.
3. Откройте PowerShell в папке проекта и один раз выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

Для установки зависимостей при первом запуске нужен доступ к интернету. После
успешной установки интернет приложению не нужен.

4. Запустите `start_demo.bat` двойным кликом. Откроется
   `http://127.0.0.1:8010`.
5. Для остановки используйте `stop_demo.bat` или нажмите `Ctrl+C` в окне сервера.

Если на новом компьютере уже лежит скопированная `.venv` и запуск сообщает о
нерабочем окружении, удалите только каталог `.venv` и повторите три команды
подготовки выше. Файл `backend\data\demo.sqlite` удалять нельзя, если требуется
сохранить внесённые данные.

Полностью автономный пакет для чистого Windows-компьютера без установленного Python
пока не собран; это следующий шаг для окончательно переносимого демо.

## Добавление рабочих сотрудников

Во вкладке `Рабочий` -> `Структура` HR добавляет руководителей и сотрудников
вручную через кнопку `Добавить людей` у нужной штатной строки.

Порядок работы:

- сначала добавить руководителя на его штатную строку;
- затем добавить сотрудников на их штатные строки;
- для сотрудника выбрать непосредственного руководителя;
- для каждого пользователя указать ФИО и email, по которому он будет входить в систему.

## Локальный запуск в разработке

Backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --port 8010
```

Frontend после установки зависимостей:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Vite проксирует запросы `/api` в backend на `http://127.0.0.1:8010`.

Для проверки собранного единого приложения:

```powershell
cd frontend
npm.cmd run build
cd ..
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --port 8010
```

После этого интерфейс доступен по адресу `http://127.0.0.1:8010`.
